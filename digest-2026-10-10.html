NO PRIORS · SARAH GUO & ELAD GIL · REFLECTION AI

"Beam: The Great American Open Model with ReflectionAI Co-Founder and CEO Misha Laskin" — 嘉宾：Misha Laskin · Co-founder & CEO, Reflection AI

核心要点

Misha Laskin 的核心判断是，开放模型不是闭源模型的便宜替代品，而会成为企业和国家级 AI 基础设施的竞争入口。

Misha Laskin 介绍 Reflection AI 推出 Beam 的背景：团队从约 30 人扩到约 300 人，补齐 pre-training、mid-training、reinforcement learning 和基础设施团队，目标是做 frontier open intelligence。他反复强调，训练大模型没有单一秘方，「everything」都要做对，人才、数据、算力、基础设施和文化缺一不可。

最有信息量的部分是 Beam 的训练结构：它是一个 500B 总参数、23B active 的模型，pre-training 使用约 6000 张 GB300，RL 则用了超过 10000 张 GB300 跑四周。Misha 认为 RL 系统已经进入「只要继续给 compute 就会继续变强」的阶段，开放模型的差异化不只是权重开放，而是把企业自有数据、eval、synthetic data 和推理效率接进来。

他对 open vs closed 的判断也很鲜明：closed model 仍会很有价值，但 token 需求会越来越多流向 open model，就像服务器世界大多运行 Linux。他还把 open model 称作基础设施的 Trojan horse，因为模型本身只是入口，真正绑定客户的是推理软件、cluster management、harness、工具链和服务能力。安全上，他反对把开放等同于失控，认为 cyber defense 和 offense 很难切开，更多研究者和企业能看见问题，反而可能让漏洞更快变浅。

"I have the belief that with enough eyeballs, most security and safety vulnerabilities become shallow as well."— Misha Laskin

ANTHROPIC ENGINEERING · ANTHROPIC · AGENT SECURITY

"How we contain Claude across products" — Anthropic Engineering

核心要点

Anthropic 的结论是，agent 安全不能只靠模型听话，必须先把环境层的爆炸半径框住。

Anthropic 这篇工程长文把 Claude 的安全问题从「要不要信任模型」转成「模型最多能碰到什么」。他们把风险拆成用户误用、模型误行为和外部攻击，再把防线拆成运行环境、模型层和外部内容。一个关键数据是，用户会批准约 93% 的权限弹窗，审批疲劳会让 human-in-the-loop 从防线变成形式。

文章最实用的经验是按产品形态匹配隔离强度：claude.ai 用临时容器，Claude Code 用本地 sandbox 和 auto mode，Claude Cowork 用 VM 控制本地文件与网络边界。Anthropic 也复盘了几类真实踩坑，包括信任弹窗前的项目配置执行、用户自己粘贴恶意 prompt 导致凭据外传、approved domain 通过 Files API 变成外泄通道，以及 VM 隔离让企业 EDR 看不见内部行为。

它对正在做 agent 产品的人很有提醒意义：允许访问某个域名，本质上是在授予该域名下所有函数能力；让 agent 读 tool output，本质上是在引入 prompt injection 面；自研 proxy、allowlist 和 orchestration 往往比成熟 hypervisor、seccomp、gVisor 更容易出问题。未来多 agent、持久记忆和 agent identity 会让这些边界更复杂，但底层原则仍然朴素：先限制文件、网络和进程，再用模型层去补概率性防护。

"The deterministic boundary is what gets hit when everything probabilistic misses."— Anthropic Engineering
