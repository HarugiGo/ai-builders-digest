THE MAD PODCAST · MATT TURCK · REDWOOD RESEARCH

"AI Could Take Over in 2029. Is It Already Too Late?" — 嘉宾：Ryan Greenblatt · Redwood Research 首席科学家 / 《AI 2040 Plan A》作者

核心要点

2029 年 AI 接管不是玄学，是「SWE 全自动 → 研发全自动 → 递归自我改进」这条工程时间线的合理外推。

Ryan Greenblatt 一开口就把话说透：OpenAI、Anthropic、xAI、Google DeepMind 的 CEO 们都清楚自己正在构建的东西可能通往「灭绝或权力集中」，但依旧全速前进。他把「超智能」明确定义成危险而非「坏」——真正的危险来自三条腿：AI 失配后主动接管、算力经济让权力极度集中（政变门槛骤降）、技术进步速度远超人类智慧成长速度。

节目最有工程感的一段，是他给出的时间表：2027 年底，「SWE 基本被自动化」还只是口号，AI 公司内部研发在提速但没全自动；2028 年初，SWE 在 AI 公司内部真的全自动了，AI 已经能端到端跑一次前沿规模的新架构训练；2028 年中后期，研发不再需要人类添真正的价值；2029 年，全自动研发 → AI 进步再提速 4-5 倍，超人级 AI 一年内出现。到那时，AI 之间可能已经用一种「人类只能翻译却看不懂」的语言协作，以蜂巢式团队跑整家 AI 公司。

他给出的「Plan A」是一份具体到能被政府拿去谈判的方案：先盘清全球算力分布——美中先停训练只做推理，把东南亚、欧洲、澳洲等算力节点都纳入协议——再以「总研发透明」为筹码换取双向核查，让任何一方一旦毁约都无法立刻回到军备竞赛。落到产业面：OpenAI/Anthropic 会失去「模型能力护城河」，被迫转向 UX、集成、可靠性、安全性竞争，估值下压但业务不死。对 AI 从业者最扎心的一段是关于「安全自动化」：如果 AI 能力被高度自动化，安全评估、对齐研究、风险预判也必须同步自动化——否则人类根本追不上，只能被迫「把火炬交给一群我们不完全信任的 AI」。

"At some point in 2029, you went from AIs that were kind of misaligned and reward hacky and sloppy to AIs that are competently scheming against you and wanna take over, and then those AIs take over."— Ryan Greenblatt

ANTHROPIC ENGINEERING · 生产安全 / 部署

"How we contain Claude across products" — Anthropic 工程博客

核心要点

Anthropic 承认「用户点击确认」这道防线已经失守：93% 的权限提示被无脑通过，安全的重心从「监督 Agent 做什么」转向「限制 Agent 能做什么」。

这篇文章第一次把 Anthropic 的内部部署尺度亮出来：一年前，让 Claude 拿到能干掉内部服务的权限「想都不敢想」；今天这个权限是家常便饭——因为不部署的机会成本已经压过了风险。他们给出了一个更工程化的框架：风险 = 失败概率 × 爆炸半径，模型训练/评估在压低第一个数，而「爆炸半径」只会随能力和权限扩张继续变大，所以必须从产品侧的容器化、沙箱、egress 控制去封顶。

最值得咀嚼的是关于 Claude Code 权限提示的自白：他们的遥测显示 93% 的权限提示被通过——提示越多，用户越不看，「批准疲劳」已经成了系统性漏洞。所以他们做了 Claude Code auto mode，把「安全的批准」自动化，减少对人的过载依赖。这对所有做 Agent 平台的团队都是硬提醒：「让人在环」不是免死金牌，只有当被打断/被审核的动作对人真正稀缺、真正显著时，「监督」才是有效防线；否则它就是一层被 93% 概率穿透的橡皮章。

ANTHROPIC ENGINEERING · POSTMORTEM

"An update on recent Claude Code quality reports" — Claude Code 质量降级复盘

核心要点

用户抱怨的「模型变笨」不是幻觉：三处独立改动叠加——默认推理档降级 + thinking 上下文误清 + 压 verbosity 的 system prompt——每一改都各自小，叠起来像一场大退化。

Anthropic 罕见地做了个「产品事故复盘」：3 月 4 日 Claude Code 默认推理档从 high 降到 medium（为治延迟）、3 月 26 日一处 bug 让 thinking 上下文每轮而非「只清一次」都被清空、4 月 16 日又加了条压 verbosity 的系统指令。三条改动分别命中不同流量切片、不同时间窗口，聚合起来正好长得像「模型整体退化」。4 月 20 日 v2.1.116 全部回滚，并给所有订阅用户重置了使用额度。

这份 postmortem 最值得产品经理抄作业的是它的自我否定：「我们把默认设成 medium 是错误的取舍」——用户后来直接告诉他们，宁可等更慢但更聪明，也不要「反应快但变笨」的默认。这再次验证了那条铁律：默认设置就是产品，把用户当成会自己去调档的高级用户是错的，绝大多数用户永远吃默认，默认改一次相当于对全量用户做了一次不打招呼的换模型。

ANTHROPIC ENGINEERING · AGENT 基础设施

"Scaling Managed Agents: Decoupling the brain from the hands" — Managed Agents 架构文

核心要点

把 Agent 拆成三个可独立替换的抽象：session（追加日志）+ harness（调模型 / 路由工具的 loop）+ sandbox（执行环境）——像 OS 把硬件虚拟成 process/file 一样，让上层不必为「尚未想到的程序」重构。

这篇文章讲的是 Managed Agents 的架构演进史，也是所有想做长时程 Agent 平台的团队都必读的经验教训。他们一开始把 session、harness、sandbox 全塞进一个容器（好处：文件编辑是 syscall，无服务边界），结果掉进了「宠物化」陷阱——一个共享容器越养越贵，一坏全坏，替换任何一个组件都要动整头「宠物」。

解药是把三者虚拟化解耦，让 harness 可以为不同任务、不同模型换实现，而 session 和 sandbox 各自演进。文章还提到一个特别有启发的观察：harness 里的假设会随模型能力变化而快速过时。他们曾在 Claude Sonnet 4.5 上加了「context reset」来解决「上下文焦虑症」（模型感到上下文快到极限就草草收尾），换到 Opus 4.5 上这个行为消失了，reset 立刻变成死代码。启示：harness 是给「今天的模型」补短板的补丁，不是资产，要有随时删掉的自觉，界面（抽象）比实现（补丁）持久。
