POST · ANTHROPIC · Claude Code

Boris Cherny — Claude Code, Anthropic

面对"到底要不要把 Claude 写的代码当人写的代码来审查"这类日常来信，Anthropic 的 Boris Cherny 给了一个业内难得清晰的双档答案：抛完就扔的原型可以当黑盒，做完能跑就行；但进生产环境的每一行 AI 代码，标准要比人写的更严——Anthropic 自己就靠大量 lint、测试、Claude 端到端测试、Claude fuzzer、自动 code review 和 security review 兜底。他把"守 bar"的责任明确留给工程师：如果 Claude 写得不够好，先升级到 Opus 5 / Fable 5.1，再把 effort 拉到 high/xhigh，把 CLAUDE.md 和 skills 写扎实，最后才是等下一个模型。搭配他同天转发的 Anthropic 威胁情报报告，双档规则的另一面也被点破：能写代码的模型也能被拿去攻击关键基础设施，能力越强、护栏越必要。

POST · META · Sr Director, AI

Madhu Guru — Sr Director AI, Meta（前 Google Gemini/Veo/Nano Banana）

评估 agent 的第一原则不是看最终答案对不对，而是看"过程"对不对。两条 agent 轨迹都答出 42，但一条搜对了源、拿对了文档、四次干净的工具调用；另一条搜了三遍同一个词、修了两次错、绕了 17 步——两者的工程价值完全不同。Madhu 给了一个可复用的落地清单：把工作流全画出来，把每一步的任务定义清楚，为每一步单独设评估（或作为大评估的一个切片），并明确"中位难度"和"高难度"两档任务，让评估反映真实分布。看 eval 报告时，先看步骤，再看最终结果。

MAD PODCAST · MATT TURCK · Recursive 创始人

"When AI Improves Itself" — 嘉宾：Richard Socher · Recursive CEO / 前 Salesforce 首席科学家

核心要点

"能被模拟的东西，AI 迟早都会解掉"——这才是 RSI 真正落地的地基。

Richard Socher 是 AI 领域被引最多的研究者之一，最新为 Recursive 融了 6.5 亿美金，其中约 4.1 亿一次性锁给了 Amazon 的算力合约。他不认可"硬起飞（hard takeoff）"叙事——不是所有事都会瞬时加速，长期临床试验、真实物理约束都会拉时间线，但他坚信 AI 会通过科学发现全面提速人类知识边界。他的新书 The Eureka Machine 把这套方法论拆成四根柱子：其一，用大模型吸收人类已有知识，同时靠开源逆向让"闭源→开源→再回到公共池"的循环把知识重新平铺开；其二，让 AI 直接吃科学仪器测量到的、语言难以描述的数据，构建一层"人类语言之外的物理/化学/生物基础模型"；其三，为不同尺度的现象搭建可验证的模拟器；其四，回到真实世界跑实验，用真机器补齐模拟未覆盖的变量。

最反直觉的一点是他对"AI 只是下一个 token 预测器"的反驳：正因为 next-token prediction 逼出了一个能压缩世界结构的世界模型，同一套技术才能同时做聊天、蛋白质结构、代码。他也把"编程"提到"最容易被 RSI 吃掉的领域"——因为软件的验证器几乎无成本可造：截图 → 生成能还原它的代码 → 自动比对，这类验证器可以被无限量制造，也就意味着可以无限量制造训练信号。药物发现不会是硬起飞，但会从"一家公司押一款药"的模式，变成"多分子并行、试错成本被算力压平"的模式。

他还讲了一段少见的公众沟通反思：AI 行业在 PR 上做得很糟——真正在用 ChatGPT / Claude Code 的人不发声，负面情绪却容易放大成道德恐慌，这跟 18 世纪骂小说、20 世纪骂电子游戏是一个模板。对 PM 和产品团队来说，值得抄走的两件事：（1）在自家场景里主动造"可验证的合成数据"，验证器数量决定进化上限；（2）把"步骤级评估"和"验证器工程化"当作团队新一年的能力储备。

"Anything you can simulate, AI will solve. And before you know it, you're in this recursive self improvement loop."— Richard Socher
